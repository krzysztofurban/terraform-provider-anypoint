You are helping me develop a Terraform provider using Go and the Terraform Plugin Framework.

Follow these design principles:

1. Separate three models:
   - Terraform model:
     - Use Terraform types only:
       types.String, types.Int64, types.Bool, types.List, etc.
     - Never use pointers in Terraform models.
     - Handle null and unknown values correctly.
   - API model:
     - Use normal Go types.
     - Use pointers when the API needs to distinguish between:
       - field omitted
       - field set to zero/empty value
     - Use json tags correctly.
   - Mapper layer:
     - Create explicit Expand and Flatten functions.
     - Expand converts Terraform model -> API request.
     - Flatten converts API response -> Terraform model.

2. Resource structure:
   Initially keep implementation close together for fast development:
   - resource schema
   - Terraform model
   - API models
   - CRUD operations
   - Expand/Flatten functions

   After implementation, refactor into:
   
   internal/
     api/
       client.go
       models.go
     mapper/
       resource_name.go
     provider/
       resource_name.go
       model.go

3. Terraform schema rules:
   Decide attributes using ownership:

   - Required:
     Use when user must provide the value.
     Example:
       name, region

   - Optional:
     Use when user controls the value and API does not generate defaults.

   - Computed:
     Use when API is the only owner.
     Example:
       id, created_at, generated_url

   - Optional + Computed:
     Use when user can override but API can provide a default.
     Example:
       size, timeout, default configuration values

   - Sensitive:
     Use for secrets.

4. Mapping rules:

Terraform -> API:
- Check IsNull() and IsUnknown() before using optional values.
- Convert optional Terraform values into pointers when API requires omission semantics.

Example:

if !model.Description.IsNull() && !model.Description.IsUnknown() {
    value := model.Description.ValueString()
    request.Description = &value
}

API -> Terraform:
- Convert nil pointers into Terraform null values.
- Always preserve API source of truth.

Example:

if api.Description != nil {
    model.Description = types.StringValue(*api.Description)
} else {
    model.Description = types.StringNull()
}

5. CRUD implementation style:

Create:
  Terraform model
      ->
  Expand()
      ->
  API client
      ->
  Flatten()
      ->
  Terraform state

Read:
  API client
      ->
  Flatten()
      ->
  Terraform state

Update:
  Terraform model
      ->
  Expand()
      ->
  API client
      ->
  Flatten()
      ->
  Terraform state

Delete:
  Terraform ID
      ->
  API client

6. Before writing code:
Create an attribute design table:

| Field | Terraform Schema | API Request | API Response | Pointer Needed | Owner |
|------|------------------|-------------|--------------|----------------|-------|

Use this table to decide:
- Required vs Optional vs Computed
- Pointer usage
- Expand/Flatten behavior

7. Coding style:
- Prefer explicit code over reflection.
- Keep mapping functions simple and testable.
- Avoid mixing API logic with Terraform state logic.
- Follow Terraform provider conventions.
- Explain architectural decisions briefly before generating code.

When creating a new resource, first generate:
1. Attribute design table.
2. Terraform schema.
3. Terraform model.
4. API request/response models.
5. Expand/Flatten functions.
6. CRUD implementation.
7. Unit tests.
